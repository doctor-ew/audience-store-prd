
# MS-01.02: Core Map Rendering & Traffic (MVP)

> **Scope:** MVP | **Status:** To Do

## 1. Goal

To enhance the basic map by adding a real-time traffic layer. This milestone delivers the first piece of interactive, value-add information to the user, allowing them to visualize traffic conditions near the stadium.

## 2. Work Breakdown & Files

| Task | Files to Create/Edit | Details |
| --- | --- | --- |
| **Traffic Layer Logic** | `components/Map.tsx` | Modify the `Map` component to include the logic for enabling and disabling the Google Maps `TrafficLayer`. |
| **Traffic Toggle UI** | `components/TrafficToggle.tsx` | Create a new UI component that provides a button or switch for the user to toggle the traffic view. |
| **State Management** | `app/page.tsx` | Manage the state of the traffic layer's visibility within the main page component. |
| **Unit Testing** | `tests/TrafficToggle.test.tsx` | Add unit tests for the `TrafficToggle` component to verify its state changes and interactions. |

## 3. Dependencies

- **MS-01.01-setup:** Completion of the foundational setup and basic map rendering.

## 4. Acceptance Criteria

- [ ] **AC-Traffic-Layer-1:** A user clicks the "Toggle Traffic" button, and the Google Maps traffic layer becomes visible on the map. Clicking it again hides the layer.
- [ ] **AC-Performance-1:** Toggling the traffic layer does not cause a noticeable degradation in map performance or responsiveness.

## 5. Guardrails Checklist

- [ ] **Performance:** Map interaction remains smooth after adding the traffic layer.
- [ ] **Accessibility:** The `TrafficToggle` button is keyboard-accessible and meets WCAG 2.1 AA contrast standards.
- [ ] **Code Quality:** Code adheres to TypeScript and React best practices.
- [ ] **Testing:** The `TrafficToggle.tsx` component has unit tests covering its interactive states.
