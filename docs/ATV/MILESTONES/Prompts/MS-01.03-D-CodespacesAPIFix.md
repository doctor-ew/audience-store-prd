# MS-01.03-D: GitHub Codespaces API Connectivity Fix

## Problem Statement
When running the MARTA transit overlay app in GitHub Codespaces, the MARTA Train API fails to connect because it uses a non-standard port (18096). GitHub Codespaces restricts outbound connections to non-standard ports for security reasons, causing the API requests to time out after 10 seconds.

### Error Symptoms
```
Fetching MARTA bus and train data...
MARTA GTFS-RT API request timed out.
Falling back to mock data
GET /api/marta 200 in 10009ms
```

## Root Cause
- **MARTA Bus API**: `https://gtfs-rt.itsmarta.com/TMGTFSRealTimeWebService/vehicle/vehiclepositions.pb` (port 443) ✅ Works
- **MARTA Train API**: `https://developerservices.itsmarta.com:18096/...` (port 18096) ❌ Blocked by Codespaces firewall

## Solution: Environment Detection + CORS Proxy

### Implementation Strategy
1. **Detect Codespaces environment** using environment variables
2. **Route train API requests through a CORS proxy** (`allorigins.win`) to bypass port restrictions
3. **Maintain direct connection** for local/production environments (better performance)

### Code Changes

**File**: `app/api/marta/route.ts`

```typescript
export async function GET() {
  const useMockData = process.env.USE_MOCK_MARTA_DATA === "true";

  // Detect if running in Codespaces
  const isCodespaces = Boolean(
    process.env.CODESPACES === "true" ||
    process.env.GITHUB_CODESPACES_PORT_FORWARDING_DOMAIN
  );

  if (isCodespaces) {
    console.log("🚀 CODESPACES DETECTED - Using proxy for MARTA API");
  }

  // ... existing mock data logic ...

  try {
    console.log("Fetching MARTA bus and train data...");

    // In Codespaces, use allOrigins proxy to bypass port restrictions
    const busUrl = "https://gtfs-rt.itsmarta.com/TMGTFSRealTimeWebService/vehicle/vehiclepositions.pb";
    const trainUrl = `https://developerservices.itsmarta.com:18096/itsmarta/railrealtimearrivals/developerservices/traindata?apiKey=${process.env.MARTA_TRAIN_API_KEY}`;

    // For Codespaces: proxy the train API (port 18096) through allOrigins
    const trainFetchUrl = isCodespaces
      ? `https://api.allorigins.win/raw?url=${encodeURIComponent(trainUrl)}`
      : trainUrl;

    console.log(`Train API URL: ${isCodespaces ? 'PROXIED via allOrigins' : 'DIRECT'}`);

    // Fetch both buses and trains in parallel
    const [busResponse, trainResponse] = await Promise.all([
      fetch(busUrl, { signal: controller.signal }),
      fetch(trainFetchUrl, { signal: controller.signal }),
    ]);

    // ... rest of processing logic ...
  }
}
```

## How It Works

### Codespaces Environment Detection
```typescript
const isCodespaces = Boolean(
  process.env.CODESPACES === "true" ||
  process.env.GITHUB_CODESPACES_PORT_FORWARDING_DOMAIN
);
```

These environment variables are automatically set by GitHub when running in Codespaces:
- `CODESPACES`: Set to `"true"` in all Codespaces environments
- `GITHUB_CODESPACES_PORT_FORWARDING_DOMAIN`: Contains the Codespaces domain for port forwarding

### CORS Proxy Usage
When Codespaces is detected, the train API URL is proxied:
```
Original: https://developerservices.itsmarta.com:18096/itsmarta/railrealtimearrivals/...
Proxied:  https://api.allorigins.win/raw?url=https%3A%2F%2Fdeveloperservices.itsmarta.com%3A18096%2F...
```

The proxy:
- Routes the request through standard port 443
- Forwards the response back to your Codespaces environment
- Adds appropriate CORS headers

## Alternative Solutions Considered

### ❌ Port Forwarding in Codespaces
- Only works for **inbound** connections TO Codespaces
- Cannot configure **outbound** firewall rules for non-standard ports
- This is a GitHub security limitation

### ❌ VPN/Tunnel Services (ngrok, etc.)
- Requires additional setup and authentication
- Not ideal for teaching/demo purposes
- Adds complexity for students

### ✅ Environment Detection + CORS Proxy (CHOSEN)
- Zero additional setup required
- Works immediately in Codespaces
- Maintains performance in production
- Clear logging for debugging
- Students can see the conditional logic
