# MS-01.01: Foundational Setup (C.R.A.F.T Framework)

## Context
Atlanta FIFA Navigator is a Next.js 15+ TypeScript application providing real-time traffic/transit navigation for Mercedes-Benz Stadium during FIFA events. Stack: Next.js App Router, TypeScript, Tailwind CSS, Google Maps JavaScript API via @googlemaps/js-api-loader, pnpm package manager, Vercel deployment, Jest/React Testing Library.

Current state: Greenfield project requiring foundational scaffolding per docs/ATV/TECH_SPEC.md. This milestone (MS-01.01) establishes core infrastructure to validate Google Maps API integration and Vercel deployment before building features. Technical risk reduction is primary goal.

Reference materials:
- docs/ATV/TECH_SPEC.md (architecture, dependencies, data model, performance targets)
- docs/ATV/MILESTONES/MS-01.01-setup.md (work breakdown, dependencies, acceptance criteria)
- docs/ATV/acceptance_criteria.md (testable success measures)
- docs/ATV/Guardrails.md (performance budgets, security mandates, code quality standards)

## Role
You are a senior full-stack engineer with deep expertise in:
- Next.js 15+ App Router patterns (server components, route handlers, layout composition)
- TypeScript strict mode configuration and type safety best practices
- Google Maps JavaScript API integration, async loading strategies, API key security
- Vercel deployment workflows, environment variable management, preview deployments
- Jest/React Testing Library setup for component and integration testing
- Performance optimization (code splitting, lazy loading, TTFB < 2s)
- Security-first development (API key protection, .env management, client/server boundaries)

## Actions
Execute the following in sequence:

**1. Project Initialization**
- Initialize Next.js 15+ project using pnpm: `pnpm create next-app@latest --typescript --tailwind --app --eslint`
- Configure `tsconfig.json` with strict mode, path aliases (@/components, @/lib, @/hooks)
- Install dependencies: `@googlemaps/js-api-loader`, `@types/google.maps`
- Set up Prettier with Tailwind plugin for consistent formatting
- Initialize git repository, create .gitignore covering .env.local, .next/, node_modules/

**2. Environment Configuration**
- Create `.env.local` with `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` (client-side access justified for Maps JavaScript API)
- Document environment variables in `.env.example` with placeholder values
- Verify .gitignore excludes .env.local to prevent credential leakage
- Plan Vercel environment variable setup for production deployment

**3. Core Layout Structure**
- Create `app/layout.tsx` with metadata (title: "Atlanta FIFA Navigator", description, viewport config)
- Implement base HTML structure with semantic tags, lang="en" attribute
- Integrate Tailwind CSS with custom theme extending Mercedes-Benz Stadium brand colors (research: #00263A navy, #C8102E red)
- Add Inter/sans-serif font via next/font for performance-optimized loading
- Establish responsive container patterns for mobile-first development

**4. Map Component Development**
- Create `components/Map.tsx` as client component ('use client' directive)
- Implement Google Maps API loader using @googlemaps/js-api-loader
- Configure map initialization: center on Mercedes-Benz Stadium (lat: 33.754542, lng: -84.402492), zoom: 15
- Set mapId for advanced markers/styling (Future: custom stadium styling)
- Add loading state with skeleton UI during API initialization
- Implement error boundary for Maps API load failures
- Ensure map canvas is responsive (100% width, min-height: 500px)
- Add ref handling for map instance to enable future feature additions

**5. Homepage Integration**
- Update `app/page.tsx` to import and render Map component
- Add page-level metadata and Open Graph tags for social sharing
- Implement Suspense boundary around Map with fallback loading state
- Verify server component optimizations (minimize client bundle)

**6. Testing Infrastructure**
- Configure Jest with next.config.js compatibility (setupFilesAfterEnv, moduleNameMapper for path aliases)
- Install @testing-library/react, @testing-library/jest-dom, jest-environment-jsdom
- Create `tests/Map.test.tsx` with basic rendering test (mock Google Maps API)
- Add test script to package.json: `"test": "jest --watch"`
- Document testing patterns for future contributors

**7. Deployment Preparation**
- Create Vercel project linked to git repository
- Configure environment variables in Vercel dashboard (NEXT_PUBLIC_GOOGLE_MAPS_API_KEY)
- Trigger initial deployment and verify preview URL
- Test map rendering on deployed preview environment
- Validate TTFB < 2s using Vercel Analytics or Lighthouse

**8. Documentation**
- Create README.md with setup instructions, architecture overview, development workflow
- Document all environment variables and how to obtain Google Maps API key
- Add troubleshooting section for common setup issues (API key restrictions, CORS)
