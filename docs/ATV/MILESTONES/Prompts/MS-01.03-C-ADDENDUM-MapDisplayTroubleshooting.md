# MS-01.03-C ADDENDUM: Map Display Troubleshooting Guide

## Issue: Google Map Not Rendering (Blank White Screen)

### Problem Description
After implementing the Map component with Google Maps API integration, the map may fail to render, showing only a blank white screen or getting stuck in a loading state. This commonly occurs due to React ref timing issues.

---

## Root Cause Analysis

### The Core Problem
When using React refs with third-party libraries like Google Maps, there's a timing issue where:

1. **Component mounts** → `useEffect` runs
2. **`useEffect` runs** → tries to access `mapRef.current`
3. **`mapRef.current` is `null`** → because the DOM element hasn't been attached yet
4. **Early return** → map never initializes

### Anti-Pattern: Conditional Rendering with Early Returns
```typescript
// ❌ WRONG: This prevents the ref from ever being created
const Map = () => {
  const mapRef = useRef<HTMLDivElement>(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    // This runs but mapRef.current is null!
    if (!mapRef.current) return;
    // Map initialization code...
  }, []);

  if (loading) {
    return <div>Loading...</div>; // ❌ mapRef div never renders!
  }

  return <div ref={mapRef} />;
};
```

**Why this fails:**
- The `loading` state starts as `true`
- Component returns early with "Loading..." div
- The `<div ref={mapRef}>` **never gets rendered**
- `mapRef.current` remains `null` forever
- `useEffect` can't initialize the map

---

## The Solution: Always Render the Ref Element

### Pattern: Use Overlays Instead of Conditional Returns
```typescript
// ✅ CORRECT: Ref element always renders, overlays show states
const Map = () => {
  const mapRef = useRef<HTMLDivElement>(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<Error | null>(null);

  useEffect(() => {
    let isMounted = true;

    const initMap = async () => {
      // Wait for ref to be available
      if (!mapRef.current) {
        setTimeout(() => {
          if (isMounted && !map) {
            initMap();
          }
        }, 100);
        return;
      }

      // Prevent double initialization
      if (map) return;

      try {
        const loader = new Loader({
          apiKey: process.env.NEXT_PUBLIC_GOOGLE_MAPS_API_KEY!,
          version: "weekly",
        });

        const { Map } = await loader.importLibrary("maps");

        if (isMounted && mapRef.current) {
          const newMap = new Map(mapRef.current, mapOptions);
          setMap(newMap);
          setLoading(false);
        }
      } catch (e) {
        if (isMounted) {
          setError(e as Error);
          setLoading(false);
        }
      }
    };

    initMap();

    return () => {
      isMounted = false;
    };
  }, [map]);

  return (
    <div className="relative w-full h-full min-h-[500px]">
      {/* Loading overlay */}
      {loading && (
        <div className="absolute inset-0 bg-gray-200 animate-pulse flex items-center justify-center z-10">
          <p>Loading map...</p>
        </div>
      )}

      {/* Error overlay */}
      {error && (
        <div className="absolute inset-0 bg-red-100 text-red-700 flex items-center justify-center z-10">
          Error: {error.message}
        </div>
      )}

      {/* Map container - ALWAYS RENDERS */}
      <div
        className="w-full h-full min-h-[500px]"
        ref={mapRef}
        data-testid="map-container"
      />
    </div>
  );
};
```

### Key Improvements

1. **Always Render Ref Element**
   - The `<div ref={mapRef}>` is always in the return statement
   - No conditional returns that prevent rendering

2. **Polling for Ref Availability**
   ```typescript
   if (!mapRef.current) {
     setTimeout(() => initMap(), 100);
     return;
   }
   ```
   - Retries initialization every 100ms until ref is available
   - Prevents errors from accessing null refs

3. **Prevent Double Initialization**
   ```typescript
   if (map) return; // Already initialized
   ```

4. **Cleanup Function**
   ```typescript
   let isMounted = true;
   return () => { isMounted = false; };
   ```
   - Prevents state updates after component unmounts

5. **Absolute Positioned Overlays**
   ```typescript
   <div className="absolute inset-0 ... z-10">
   ```
   - Shows loading/error states without unmounting the map container

## Debugging Checklist

### Step 1: Verify Environment Variables
```bash
# Check .env file exists
ls -la .env .env.local

# Verify API key is set
cat .env | grep NEXT_PUBLIC_GOOGLE_MAPS_API_KEY
```

**Common issues:**
- ❌ `.env` file doesn't exist (only `.env.sample`)
- ❌ Missing `NEXT_PUBLIC_` prefix (Next.js requirement for client-side vars)
- ❌ Dev server not restarted after adding `.env`

**Solution:**
```bash
cp .env.sample .env
# Add your API key to .env
# RESTART dev server: Ctrl+C then npm run dev
```

### Step 2: Check Console for Ref Issues
Add debug logging:
```typescript
useEffect(() => {
  const initMap = async () => {
    console.log("mapRef.current:", mapRef.current); // Should NOT be null
    console.log("API Key:", process.env.NEXT_PUBLIC_GOOGLE_MAPS_API_KEY ? "Present" : "Missing");

    if (!mapRef.current) {
      console.log("Waiting for mapRef...");
      // ... retry logic
    }
  };
}, []);
```

**What to look for:**
- ✅ "mapRef.current: div" → Good, ref is attached
- ❌ "mapRef.current: null" → Ref not rendering
- ❌ "Waiting for mapRef..." repeating infinitely → Ref element not in DOM

### Step 3: Verify DOM Structure
Inspect Elements tab in browser:
```html

```

## Common Errors and Solutions

### Error: "mapRef.current is null"
**Symptom:** Console shows ref is null, map never initializes

**Cause:** Ref element not rendering due to early return

**Fix:** Use overlay pattern (see above)

---

### Error: Infinite "Waiting for mapRef..." loop
**Symptom:** Console spam with "Waiting for mapRef..."

**Cause:** Ref div never gets added to DOM

**Fix:** Ensure ref div is in the return statement, not behind a conditional

---

### Error: Map flashes then disappears
**Symptom:** Map loads briefly then goes blank

**Cause:** Component re-rendering and unmounting the ref div

**Fix:** Add dependency array to `useEffect` to prevent re-initialization:
```typescript
useEffect(() => {
  // initialization code
}, [map]); // Only run when map is null/undefined
```

---

### Error: "InvalidKeyMapError" or "RefererNotAllowedMapError"
**Symptom:** Red error overlay on map

**Cause:**
- Invalid Google Maps API key
- API key restrictions preventing localhost

**Fix:**
1. Verify API key in Google Cloud Console
2. Enable "Maps JavaScript API"
3. Add `http://localhost:3000` to API key restrictions

## Summary

**The Golden Rule:** When using refs with third-party libraries in React:
- ✅ Always render the ref element
- ✅ Use overlays for loading/error states
- ✅ Poll for ref availability if needed
- ❌ Never conditionally return before rendering the ref element

This pattern ensures the DOM element is always available for the ref to attach to, preventing the "ref is null" timing issue.
