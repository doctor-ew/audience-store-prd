# MS-02.01-C: Component Translation Integration (P.R.O.M.P.T Framework)

## Problem
Components have hardcoded English strings. Need to replace all text with `useTranslation` hook calls for bilingual support.

**User impact:** Switching language (MS-02.01-B) only changes switcher UI—all other components remain English.

## Requirements
**Must-haves:**
- Replace hardcoded strings with `t('translation.key')` calls
- Update all components: TrafficToggle, Map, error messages
- Update aria-labels and accessibility strings
- No English "leakage" in Spanish mode

**Must-NOTs:**
- Do NOT translate API data (MARTA responses)
- Do NOT translate Google Maps UI

## Methods

### Update Pattern
**Before (hardcoded):**
```typescript
<button aria-label="Toggle traffic layer visibility">
  Toggle Traffic
</button>
```

**After (translated):**
```typescript
import { useTranslation } from 'react-i18next';

const { t } = useTranslation();

<button aria-label={t('map.toggleTrafficAriaLabel')}>
  {t('map.toggleTraffic')}
</button>
```

### Components to Update

**1. TrafficToggle.tsx:**
```typescript
const { t } = useTranslation();
return (
  <button aria-label={t('map.toggleTrafficAriaLabel')}>
    {t('map.toggleTraffic')}
  </button>
);
```

**2. Map.tsx (messages):**
```typescript
const { t } = useTranslation();

// Loading state
{isLoading && <div>{t('transit.loading')}</div>}

// Error state
{isError && <div>{t('transit.apiError')}</div>}

// Empty state
{vehicles?.length === 0 && <div>{t('transit.noData')}</div>}
```

**3. Metadata (use client component):**
```typescript
// components/MetadataProvider.tsx
useEffect(() => {
  document.title = t('app.title');
}, [t]);
```

## Parameters

**Translation coverage checklist:**
- Button text
- Headings
- Status messages (loading, error, success)
- aria-labels, aria-describedby
- Error boundary messages

**Layout considerations:**
- Spanish text 20-30% longer than English
- Test button widths don't break
- Verify no text truncation
- Test mobile view (375px width)
