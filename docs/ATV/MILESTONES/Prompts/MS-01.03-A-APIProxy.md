# MS-01.03-A: MARTA API Proxy (M.A.P.S Framework)

## Mission
Build secure server-side API route (`/app/api/marta/route.ts`) that proxies requests to MARTA's real-time transit API, protecting the API key while delivering vehicle location data in <500ms.

**Core requirement:** MARTA_API_KEY must remain server-side only.

## Audience
- **Primary consumer:** `hooks/useMartaData.ts` (built in MS-01.03-B)
- **Expects:** JSON response with array of TransitVehicle objects
- **Needs:** <500ms response, reliable error handling, typed data

## Parameters

### MARTA API Contract
**Endpoint:** `https://developerservices.itsmarta.com/BRDRestService/RestBusRealTimeService/GetAllBus`
- Authentication: API key via query parameter
- Method: GET
- Response: JSON array of vehicles with VEHICLE, LATITUDE, LONGITUDE, ROUTE fields
- Rate limit: 60 requests/minute

### Environment Setup
Add to `.env.local` and Vercel:
```
MARTA_API_KEY=your_marta_api_key_here
```

### Data Schema
Normalize MARTA response to internal format:
```typescript
interface TransitVehicle {
  id: string;
  type: 'bus' | 'train';
  latitude: number;
  longitude: number;
  route: string;
}
```

### Zod Validation
```typescript
import { z } from 'zod';

const MartaVehicleSchema = z.object({
  VEHICLE: z.string(),
  LATITUDE: z.string(),
  LONGITUDE: z.string(),
  ROUTE: z.string(),
});
```

## Success Criteria

**Implementation requirements:**
- [ ] API route at `app/api/marta/route.ts`
- [ ] Validate MARTA_API_KEY exists (throw error if missing)
- [ ] Fetch with 400ms timeout (AbortController)
- [ ] Validate response with Zod before returning
- [ ] Normalize string coordinates to numbers
- [ ] Return 200 on success, 503 on MARTA API failure, 500 on other errors
- [ ] Log errors to console for debugging

**Core GET handler structure:**
```typescript

  // 1. Check MARTA_API_KEY exists

  // 5. Normalize format (string coords → numbers, VEHICLE → id)
  // 6. Return JSON { vehicles: TransitVehicle[] }

}
```
