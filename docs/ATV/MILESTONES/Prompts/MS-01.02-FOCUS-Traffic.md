# MS-01.02: Core Map Rendering & Traffic (F.O.C.U.S Framework)

## Frame
**Scope boundaries:**
- IN SCOPE: Google Maps TrafficLayer integration, UI toggle component, state management for layer visibility, accessibility compliance, unit testing
- OUT OF SCOPE: Custom traffic data visualization, historical traffic analysis, route planning with traffic considerations, backend traffic API proxying (Google Maps handles traffic client-side)
- PRECONDITIONS: MS-01.01 complete (Map component rendering, Google Maps API initialized, Vercel deployed)
- POSTCONDITIONS: Users can toggle real-time traffic overlay; map remains performant; accessibility standards maintained

**File modification boundaries:**
- MODIFY: `components/Map.tsx` (add TrafficLayer instantiation, props for toggle control)
- CREATE: `components/TrafficToggle.tsx` (new UI component), `tests/TrafficToggle.test.tsx` (unit tests)
- MODIFY: `app/page.tsx` (state management for traffic visibility)
- NO CHANGES: API routes, environment config, layout structure

**Technology constraints:**
- Use Google Maps JavaScript API TrafficLayer class (native implementation, no custom rendering)
- State management: React useState at page component level (avoid over-engineering for single boolean)
- Styling: Tailwind CSS classes matching existing design system
- Icons: Use lucide-react or heroicons for toggle button iconography
- Testing: Jest + React Testing Library (no Playwright/E2E for this milestone)

## Objective
**Primary goal:** Empower users to visualize real-time traffic conditions around Mercedes-Benz Stadium to inform transportation decisions during FIFA events.

**Specific deliverables:**
1. Functional traffic layer toggle button accessible from map interface
2. TrafficLayer rendering on Google Maps instance when toggle is active
3. Smooth state transitions (toggle on/off) without map re-initialization
4. Keyboard-accessible toggle meeting WCAG 2.1 AA standards (focus indicators, aria-labels)
5. Unit test coverage for TrafficToggle component (interaction states, accessibility attributes)
6. Performance validation: no degradation in map responsiveness when layer active

**User journey:**
1. User lands on homepage with map rendered (default: traffic layer OFF)
2. User clicks "Toggle Traffic" button (or presses Enter when focused)
3. Traffic layer appears as colored overlay on roads (green/yellow/red indicating congestion)
4. User clicks again to hide traffic layer
5. Map remains centered, zoom level unchanged, interaction smooth

## Constraints
**Technical constraints:**
- MUST use Google Maps TrafficLayer API (do not attempt custom traffic rendering)
- MUST NOT introduce additional API keys or external traffic data sources
- MUST maintain TTFB < 2s for page load (traffic layer loads asynchronously after map)
- MUST ensure toggle button has minimum 44x44px touch target (mobile accessibility)
- MUST use semantic HTML (<button>, not <div> with onClick)
- MUST preserve existing Map component prop interface (backward compatibility for future milestones)

**Performance constraints:**
- TrafficLayer instantiation MUST NOT block map interactivity (async loading)
- Toggle state changes MUST complete within 100ms (perceived instant feedback)
- No memory leaks from repeated toggle actions (proper cleanup of TrafficLayer instance)

**Accessibility constraints (WCAG 2.1 AA):**
- Toggle button MUST have descriptive aria-label: "Toggle traffic layer visibility"
- Button MUST indicate current state via aria-pressed attribute (true/false)
- Focus indicator MUST meet 3:1 contrast ratio against background
- Button MUST be keyboard-operable (Space/Enter key support)
- State changes MUST be announced to screen readers (consider aria-live region)

**Code quality constraints:**
- TypeScript strict mode (no `any` types, explicit return types for functions)
- ESLint passing (pnpm lint)
- Prettier formatting enforced
- Component must be pure/idempotent (no side effects in render)
