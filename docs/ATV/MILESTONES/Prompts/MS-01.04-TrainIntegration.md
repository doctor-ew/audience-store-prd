# MS-01.04: MARTA Train Integration (M.A.P.S Framework)

## Mission
Extend the MARTA API proxy endpoint to fetch and display real-time train positions alongside bus data, combining both transit types into a unified vehicle feed.

**Core requirement:** Fetch train data from MARTA REST API, deduplicate by TRAIN_ID, and merge with bus data from GTFS-Realtime feed.

## Audience
- **Primary consumer:** `components/TransitMarkers.tsx` (displays both buses and trains)
- **Expects:** JSON response with array of TransitVehicle objects (type: "bus" | "train")
- **Needs:** Combined bus + train data, deduplication, consistent format

## Parameters

### MARTA Train API
**Endpoint:** `https://developerservices.itsmarta.com:18096/itsmarta/railrealtimearrivals/developerservices/traindata?apiKey=YOUR_KEY`
- **Authentication:** API key via query parameter
- **Method:** GET
- **Response:** JSON array of train entries
- **Data:** Multiple entries per train (one for each upcoming station)
- **Update frequency:** Real-time

### Environment Setup
Add to `.env` and `.env.local`:
```bash
# MARTA Train API Key
MARTA_TRAIN_API_KEY=your-train-api-key-here
```

**Important:** This is a server-side only variable (no `NEXT_PUBLIC_` prefix).

### Train API Response Format
Each train appears multiple times in the response (once per station it's approaching):
```json
[
  {
    "TRAIN_ID": "306506",
    "LATITUDE": "33.7490",
    "LONGITUDE": "-84.3880",
    "LINE": "GOLD",
    "STATION": "FIVE POINTS STATION"
  },
  {
    "TRAIN_ID": "306506",
    "LATITUDE": "33.7490",
    "LONGITUDE": "-84.3880",
    "LINE": "GOLD",
    "STATION": "PEACHTREE CENTER STATION"
  }
]
```

**Deduplication required:** The same `TRAIN_ID` appears multiple times. Use a Map to deduplicate by `TRAIN_ID`.

### TransitVehicle Schema
```typescript
interface TransitVehicle {
  id: string;
  type: 'bus' | 'train';
  latitude: number;
  longitude: number;
  route: string;
}
```

**Core GET handler structure:**
```typescript
export async function GET() {
  const useMockData = process.env.USE_MOCK_MARTA_DATA === "true";

  if (useMockData) {
    return NextResponse.json({ vehicles: mockDataArray });
  }

  const controller = new AbortController();
  const timeoutId = setTimeout(() => controller.abort(), 10000);

  try {
    // 1. Fetch buses and trains in parallel
    const [busResponse, trainResponse] = await Promise.all([
      fetch("https://gtfs-rt.itsmarta.com/..."),
      fetch(`https://developerservices.itsmarta.com:18096/itsmarta/railrealtimearrivals/developerservices/traindata?apiKey=${process.env.MARTA_TRAIN_API_KEY}`)
    ]);

    clearTimeout(timeoutId);

    // 2. Process buses (GTFS-RT protobuf)
    let buses: TransitVehicle[] = [];
    if (busResponse.ok) {
      // Decode protocol buffer, map to TransitVehicle format
    }

    // 3. Process trains (JSON, deduplicate by TRAIN_ID)
    let trains: TransitVehicle[] = [];
    if (trainResponse.ok) {
      const trainData = await trainResponse.json();

      // Deduplicate by TRAIN_ID
      const trainMap = new Map<string, any>();
      trainData.forEach((train: any) => {
        if (train.TRAIN_ID && train.LATITUDE && train.LONGITUDE) {
          trainMap.set(train.TRAIN_ID, train);
        }
      });

      trains = Array.from(trainMap.values())
        .map((train) => ({
          id: train.TRAIN_ID,
          type: "train" as const,
          latitude: parseFloat(train.LATITUDE),
          longitude: parseFloat(train.LONGITUDE),
          route: train.LINE || "Unknown",
        }))
        .filter((v) => v.latitude !== 0 && v.longitude !== 0);
    }

    // 4. Combine and return
    const vehicles = [...buses, ...trains];

    // 5. Fallback only if both failed
    if (vehicles.length === 0) {
      return NextResponse.json({ vehicles: mockDataArray });
    }

    return NextResponse.json({ vehicles });
  } catch (error) {
    return NextResponse.json({ vehicles: mockDataArray });
  }
}
```

## Common Issues and Solutions

### Issue: No trains appearing on map
**Symptoms:** Only bus markers visible

**Debugging steps:**
```bash
# Check if train API is returning data
curl "https://developerservices.itsmarta.com:18096/itsmarta/railrealtimearrivals/developerservices/traindata?apiKey=YOUR_KEY" | jq '.[0]'

# Check server logs for train count
# Should see: "Returning X unique train positions"
```

**Common causes:**
1. Missing or invalid `MARTA_TRAIN_API_KEY` in `.env`
2. Train API is down (rare but possible)
3. No trains running (late night hours)
4. All trains have invalid positions (lat/lng = 0)

**Solutions:**
1. Verify API key in `.env` and `.env.local`
2. Restart dev server after adding env vars
3. Check time of day (fewer trains at night)
4. Check server console logs for error messages

### Issue: Duplicate train markers
**Symptoms:** Multiple markers at same position with same TRAIN_ID

**Cause:** Deduplication not working (not using Map or using wrong key)

**Fix:** Ensure using `Map` with `TRAIN_ID` as key:
```typescript
const trainMap = new Map<string, any>();
trainData.forEach((train) => {
  trainMap.set(train.TRAIN_ID, train); // Key by TRAIN_ID
});
```

### Issue: Timeout errors when fetching trains
**Symptoms:** "API request timed out" in console

**Cause:** 10-second timeout may be too short during high traffic

**Fix:** Train API is usually fast (<500ms), but if needed, increase timeout:
```typescript
const timeoutId = setTimeout(() => controller.abort(), 15000); // 15 seconds
```

## Data Characteristics

**MARTA Rail System:**
- **Lines:** RED, GOLD, BLUE, GREEN
- **Active trains:** 10-30 trains typically active during peak hours
- **Off-peak:** 5-15 trains during non-peak times
- **Late night:** 0-5 trains (reduced service)

**API Response Size:**
- Raw response: 50-150 entries (with duplicates)
- After deduplication: 10-30 unique trains
- Each entry: ~200 bytes JSON
- Total payload: ~10-30 KB

## Performance Considerations

**Parallel fetching benefits:**
- Bus API: ~200ms response time
- Train API: ~300-500ms response time
- Sequential: 500-700ms total
- Parallel: ~500ms total (faster of the two + overhead)

**Deduplication performance:**
- Map lookup: O(1) per entry
- 150 entries: <1ms deduplication time
- Negligible overhead
