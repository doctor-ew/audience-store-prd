# MS-01.03-A ADDENDUM: MARTA API Troubleshooting Guide

## Issue: MARTA API Returning 503 Errors or Timeouts

### Problem Description
After implementing the MARTA API proxy endpoint, transit markers fail to appear on the map. The API returns 503 Service Unavailable errors, and the map displays "No transit data available."

---

## Root Cause Analysis

### Common Issues with External APIs

1. **Incorrect Authentication Method**
   - Using header-based auth when API expects query parameters
   - Wrong header name or format

2. **Timeout Too Aggressive**
   - Setting timeout too short for external API response times
   - External APIs can be slow or unreliable

3. **API Service Unavailability**
   - Third-party APIs can go down
   - Rate limiting or service degradation
   - Network connectivity issues

4. **Missing Fallback Strategy**
   - No graceful degradation when API fails
   - Poor user experience during outages

---

## Debugging Process

### Step 1: Check API Authentication Method

**Problem:** Milestone documentation says "API key via query parameter" but implementation used headers.

#### Anti-Pattern: Header-Based Authentication
```typescript
// ❌ WRONG: MARTA API doesn't accept header-based auth
const response = await fetch(
  `https://developerservices.itsmarta.com/BRDRestService/RestBusRealTimeService/GetAllBus`,
  {
    headers: {
      "api-key": apiKey,  // ❌ Wrong authentication method
    },
  }
);
```

#### Correct Pattern: Query Parameter Authentication
```typescript
// ✅ CORRECT: MARTA API expects query parameter
const response = await fetch(
  `https://developerservices.itsmarta.com/BRDRestService/RestBusRealTimeService/GetAllBus?apikey=${apiKey}`,
  {
    signal: controller.signal,
  }
);
```

**How to identify:**
1. Read API documentation carefully for auth requirements
2. Test with `curl` to verify correct authentication:
   ```bash
   # Test with query parameter
   curl "https://api.example.com/data?apikey=YOUR_KEY"

   # Test with header
   curl -H "api-key: YOUR_KEY" "https://api.example.com/data"
   ```

---

### Step 2: Adjust Timeout for Real-World API Performance

**Problem:** 400ms timeout is too aggressive for external APIs.

#### Anti-Pattern: Overly Aggressive Timeout
```typescript
// ❌ WRONG: 400ms is too short for external APIs
const controller = new AbortController();
const timeoutId = setTimeout(() => controller.abort(), 400);
```

**Why 400ms fails:**
- External APIs often take 500ms - 2000ms to respond
- Network latency varies by location and conditions
- API servers may experience temporary slowdowns

#### Correct Pattern: Reasonable Timeout with Fallback
```typescript
// ✅ CORRECT: 10 second timeout for external APIs
const controller = new AbortController();
const timeoutId = setTimeout(() => controller.abort(), 10000); // 10 seconds

try {
  const response = await fetch(url, { signal: controller.signal });
  // ... handle response
} catch (error) {
  if (error.name === "AbortError") {
    console.error("API request timed out");
    // Return fallback data or cached data
  }
}
```

**Timeout Guidelines:**
- **Internal APIs:** 500ms - 2000ms
- **External APIs:** 5000ms - 10000ms
- **Critical data:** Implement caching and fallbacks
- **User experience:** Show loading states, don't hang indefinitely

### Step 3: Implement Mock Data and Fallback Strategy

**Problem:** When external APIs fail, users see errors instead of a degraded but functional experience.

#### The Solution: Graceful Degradation with Mock Data

```typescript
// Mock data for demonstration and fallback
const MOCK_MARTA_DATA = [
  { VEHICLE: "BUS001", LATITUDE: "33.755", LONGITUDE: "-84.405", ROUTE: "1" },
  { VEHICLE: "BUS002", LATITUDE: "33.752", LONGITUDE: "-84.400", ROUTE: "2" },
  { VEHICLE: "BUS003", LATITUDE: "33.758", LONGITUDE: "-84.410", ROUTE: "3" },
  { VEHICLE: "BUS004", LATITUDE: "33.750", LONGITUDE: "-84.395", ROUTE: "4" },
  { VEHICLE: "BUS005", LATITUDE: "33.760", LONGITUDE: "-84.408", ROUTE: "5" },
];

export async function GET(request: NextRequest) {
  const useMockData = process.env.USE_MOCK_MARTA_DATA === "true";

  // Option 1: Explicit mock mode for development/demos
  if (useMockData) {
    console.log("Using mock MARTA data for demonstration");
    return NextResponse.json({ vehicles: formatMockData() });
  }

  try {
    const response = await fetch(martaApiUrl, { signal: controller.signal });

    if (!response.ok) {
      console.error(`MARTA API failed with status: ${response.status}`);
      console.log("Falling back to mock data");
      // Option 2: Automatic fallback on API failure
      return NextResponse.json({ vehicles: formatMockData() });
    }

    const data = await response.json();
    const parsedData = MartaResponseSchema.safeParse(data);

    if (!parsedData.success) {
      console.log("Invalid API response, falling back to mock data");
      // Option 3: Fallback on validation failure
      return NextResponse.json({ vehicles: formatMockData() });
    }

    return NextResponse.json({ vehicles: formatData(parsedData.data) });
  } catch (error) {
    if (error.name === "AbortError") {
      console.error("API timeout, falling back to mock data");
      // Option 4: Fallback on timeout
      return NextResponse.json({ vehicles: formatMockData() });
    }
    throw error;
  }
}
```

## Common Error Scenarios

### Error 1: 503 Service Unavailable

**Symptoms:**
- "No transit data available" message on map
- Console shows 503 errors
- Network tab shows failed requests

**Causes:**
- MARTA API is down or experiencing issues
- Timeout too short (API can't respond in time)
- Rate limiting

**Solutions:**
1. Enable mock data: `USE_MOCK_MARTA_DATA=true`
2. Increase timeout to 10+ seconds
3. Implement automatic fallback (already done in updated code)

---

### Error 2: Authentication Errors (401/403)

**Symptoms:**
- 401 Unauthorized or 403 Forbidden errors
- API returns error JSON instead of vehicle data

**Causes:**
- Invalid API key
- Wrong authentication method (header vs query param)
- API key restrictions (IP whitelist, domain restrictions)

**Solutions:**
1. Verify API key is correct in `.env`
2. Check authentication method matches API documentation
3. Contact API provider to verify key status

---

### Error 3: Timeout Errors

**Symptoms:**
- "MARTA API request timed out" in console
- Long delay before error appears

**Causes:**
- Timeout value too low (400ms is too aggressive)
- Network issues
- API server slow to respond

**Solutions:**
1. Increase timeout: `setTimeout(() => controller.abort(), 10000)`
2. Implement caching to reduce API calls
3. Use mock data as fallback

---

### Error 4: Invalid Data Structure

**Symptoms:**
- "Invalid data structure from MARTA API" error
- Zod validation fails

**Causes:**
- API response format changed
- API returns error in unexpected format
- Empty response

**Solutions:**
1. Log the actual response to inspect structure
2. Update Zod schema if API changed
3. Add fallback for validation failures (already implemented)

## Production Considerations

### Caching Strategy

For production, implement caching to reduce API calls:

```typescript
// Simple in-memory cache
let cachedData: { vehicles: TransitVehicle[]; timestamp: number } | null = null;
const CACHE_TTL = 30000; // 30 seconds

export async function GET(request: NextRequest) {
  // Check cache first
  if (cachedData && Date.now() - cachedData.timestamp < CACHE_TTL) {
    console.log("Returning cached data");
    return NextResponse.json({ vehicles: cachedData.vehicles });
  }

  try {
    // Fetch from API...
    const vehicles = await fetchFromMartaAPI();

    // Update cache
    cachedData = { vehicles, timestamp: Date.now() };

    return NextResponse.json({ vehicles });
  } catch (error) {
    // Return stale cache if available
    if (cachedData) {
      console.log("API failed, returning stale cache");
      return NextResponse.json({ vehicles: cachedData.vehicles });
    }

    // Otherwise fallback to mock data
    return NextResponse.json({ vehicles: formatMockData() });
  }
}
```

## Summary

**Key Lessons:**

1. **Authentication Method Matters:** Always verify whether the API expects headers, query parameters, or body parameters for authentication.

2. **Timeouts Must Be Realistic:** 400ms is too aggressive for external APIs. Use 5-10 seconds and implement fallbacks.

3. **Fallback Strategies Are Essential:** External APIs fail. Plan for it with:
   - Mock data for demonstrations
   - Automatic fallback on errors
   - Caching for resilience
   - User-friendly error messages

4. **Test Early with cURL:** Before implementing in code, verify the API works as expected with command-line tools.

5. **Environment Variables for Flexibility:** Use env vars like `USE_MOCK_MARTA_DATA` to easily switch between real and mock data for different scenarios.

**The Golden Rule:** External APIs are unreliable. Always implement graceful degradation to maintain user experience during failures.
