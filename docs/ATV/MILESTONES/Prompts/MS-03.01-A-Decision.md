# MS-03.01-A: Database Architecture Decision (D.E.C.I.D.E Framework)

## Define
**Decision:** Select persistent database for user preferences (language, favorites), replacing localStorage from MS-02.01.

**Problem:** localStorage → data loss on browser clear, no cross-device sync, no analytics.

**Why now:** Cross-device consistency needed, Firebase Auth prerequisite (roadmap MS-04.x).

## Enumerate
1. **Firebase Firestore** (Tech Spec specified) - NoSQL, free 50K reads/day, Firebase Auth integration
2. **Vercel Postgres** - SQL, Vercel-native, free 256MB, Prisma support
3. **Supabase** - Open-source, PostgreSQL, free 500MB, built-in auth
4. **localStorage** - Defer decision, accept limitations

## Criteria

| Criterion | Weight | Firestore | Vercel PG | Supabase | localStorage |
|-----------|--------|-----------|-----------|----------|--------------|
| Tech Spec Alignment | 25% | 5 | 2 | 2 | 1 |
| Future Auth | 15% | 5 | 2 | 4 | 1 |
| Cost (10K users) | 15% | 5 | 5 | 5 | 5 |
| Performance | 10% | 4 (200ms) | 5 (100ms) | 4 (200ms) | 5 (0ms) |

**Scores:** Firestore 4.55, Vercel PG 3.8, Supabase 3.5, localStorage 2.0

## Decide
**Selected: Firebase Firestore**

**Rationale:**
- Tech Spec compliance (explicit requirement)
- Firebase Auth integration path clear
- $0 at MVP scale (1.5M reads, 1M writes free)
- Performance <500ms meets requirements

**Trade-offs:**
- Vendor lock-in (mitigated by simple data model)
- NoSQL constraints (acceptable for preferences)
