
# MS-01.03: Transit Overlay (MVP)

> **Scope:** MVP | **Status:** To Do

## 1. Goal

To show the real-time locations of MARTA buses and trains on the map. This provides critical information for fans using public transit.

---

## 2. Key Outcomes for Stakeholders

- [ ] **See Live Transit:** Users can see icons representing MARTA buses and trains moving on the map.
- [ ] **Data is Real-Time:** The location of the transit icons updates automatically to reflect their current position.
- [ ] **Secure Data Connection:** The connection to the MARTA data feed is secure and reliable.
- [ ] **Handles Missing Data:** If transit data is unavailable, the map will show a clear message to the user.

---

## 3. Technical Task Checklist

- [ ] **Build MARTA API Route:** Create a secure, server-side API route to fetch data from the official MARTA API.
- [ ] **Implement Data Fetching:** Use a data fetching hook (`useSWR`) on the frontend to get transit data from our new API route.
- [ ] **Render Transit Icons:** Update the `Map` component to display custom markers for each vehicle at its live coordinates.
- [ ] **Write Integration Tests:** Create automated tests for the MARTA API route to ensure it's reliable and handles errors.
- [ ] **Write Unit Tests:** Add tests for the data fetching hook.

---

## 4. Key Metrics & Criteria

- **Acceptance Criteria:** Must meet `AC-MARTA-API-1`, `AC-MARTA-API-2`, `AC-Transit-Viz-1`, `AC-Transit-Viz-2`.
- **Performance:** The MARTA API route must respond in under 500 milliseconds.
- **Security:** The MARTA API key must not be publicly exposed.
- **Reliability:** The app must not crash if the MARTA data feed is down; it must show a message instead.
- **Testing:** Automated integration and unit tests must pass.
