
# MS-03.01: Database Integration (Future)

> **Scope:** Future | **Status:** To Do

## 1. Goal

To replace local storage-based user preferences with a persistent, server-side solution using Firebase Firestore. This enables a consistent user experience across multiple devices and sessions.

## 2. Work Breakdown & Files

| Task | Files to Create/Edit | Details |
| --- | --- | --- |
| **Firebase SDK Setup** | `lib/firebase.ts` | Initialize the Firebase Admin SDK for server-side use. |
| **Preferences API** | `app/api/preferences/route.ts` | Create a new API route with `GET` and `POST` methods to load and save user preferences to Firestore. |
| **Prisma Schema (Local)** | `prisma/schema.prisma` | Define the `UserPreference` model for local development and testing with SQLite. |
| **State Management Update** | `store/usePreferences.ts` | Refactor the preferences hook to interact with the `/api/preferences` endpoint instead of local storage. |
| **Integration Testing** | `tests/api/preferences.test.ts` | Add integration tests for the preferences API route to validate database interactions. |

## 3. Dependencies

- **MS-02.01-ux_polish:** Completion of the UX Polish milestone.
- **Firebase Project:** A configured Firebase project with Firestore enabled.

## 4. Acceptance Criteria

- [ ] **AC-User-Prefs-1:** A user's preferences (e.g., language) are saved to and loaded from Firestore when they are logged in (or identified by a session).
- [ ] **AC-API-Security-1:** The `/api/preferences` endpoint is secure and can only be accessed by the authenticated/authorized user.

## 5. Guardrails Checklist

- [ ] **Security:** Firebase service account keys are stored securely as environment variables. All API requests are validated using Zod.
- [ ] **Performance:** The preferences API route responds in < 500 ms.
- [ ] **Reliability:** The application gracefully handles cases where the database is unavailable.
- [ ] **Testing:** The `/api/preferences` route has comprehensive integration tests.
